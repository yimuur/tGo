方案材质关系产品改动点风险 / 代价
A 现状 矩形=木料（留白无木纹）；方形画布居中 无（对照） 留白与棋盘同色但无木纹 → 观感“半截木料”
B 方案 1 整块矩形木料（木纹贯穿）；棋盘仍居中 木纹绘制从「棋盘静态层」上移到「容器级整块木料层」：新增一层木料纹画布（或容器背景层），棋盘静态层不再自绘木纹（避免同图案叠加加深） 需保证两层木纹同源同尺度；棋盘“放大（board zoom）”时留白层的纹理缩放关系要定义（建议：留白层随画布同步缩放）
C/D/E 方案 2 方形木料板 **浮起** 于背景面（布/台面）之上 棋盘容器由矩形的 .board-wrap 改为方形 .board-panel（.board-wrap 退为背景面、去阴影）；台面材质新增 token（页面底色/毡布/同料压暗三档） 改动面大于 B：需核对所有以 .board-wrap 为锚的 UI/代码（toast 的棋盘查询、终局提示桥、画布定位兜底等）→ 顺带收益：容器恒方形，这些锚点不再错位
F 建议 不留留白：容器收到正方形，两侧露页面背景 仅改容器尺寸规则（.board-wrap 由“宽度驱动”改“高度驱动 + 居中”） 改动最小；“两侧空”由页面背景承担，不再是任何“面”
ES/C/D/F 差异仅为「背景面材质」：C＝页面底色（不引入新材质）、D＝深色毡布（最像“真实棋盘垫布”）、 E＝同料压暗台面（木料延续 + 高度感）。三者均为纯 CSS 背景，不改逻辑。
